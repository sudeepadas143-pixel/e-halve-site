PRIVATE PATH

A follower can choose to be paid in shielded ZEC instead of through X Money. The amount stays public. The address it goes to does not.

Not live. The program is not deployed. The payout worker has not been tested against NEAR Intents.

§1

WHAT IT IS

The private path is opt-in. It is one flag on a follower's roster entry. The attestor sets it with bind, after the follower proves the handle with a post on X. A new bind is the only way to change it.

The flag changes who the hand sends money to. It does not change how much. A tick never reads it. A private follower and a public follower in the same window get the same amount, to the cent.

No address is ever written on chain. The program does not know where a private payout goes.

§2

WHAT STAYS PUBLIC

Totals, burns and amounts stay public. Every tick, every burn, every order and its amount in cents are on chain, the same as for everyone else. The private flag is public too. Anyone can see which handles chose this path.

The hand's USDC deposit for each private order is a public Solana transfer of the same amount. Anyone can match it to the order. What stays hidden is the Zcash address the ZEC lands in.

§3

WHO SEES WHAT

partysees
the publicorder amounts, the flag, the hand's deposit into the swap. not the zcash address.
the operatorthe handle-to-address mapping. the operator runs the worker and can read every address on file.
near intentsthe destination address and the amount of each swap. whether its explorers publish that has not been checked.
the programthe flag only. never an address.

This is privacy from the public, not from the operator.

§4

HOW A PAYOUT MOVES

stepwhat happens
1. opt inthe follower proves the handle. the attestor binds the flag. the operator issues a submission token.
2. submitthe follower sends a Sapling address (zs1) with the token. it is encrypted at rest. it is never logged.
3. tickthe tick writes the order like any other. same window, same weight, same 25 cent floor.
4. swapthe worker quotes USDC to ZEC through NEAR Intents, sends the order's exact USDC, and waits for the result.
5. deletewhen the swap succeeds the address is deleted. the next private order needs a new submission.
6. settlethe hand settles the order on chain. the reference it records says nothing about the recipient.

Each order is paid at most once. The worker writes every step down before it takes it. A failed or refunded swap is retried. An unclear one stops and waits for a person.

§5

WHAT IS NOT DONE

itemstatus
near intentsno live test yet. the worker follows the published API. no quote, deposit or swap has been run against the real service. delivery to a shielded address has not been confirmed.
programnot deployed. the flag and its tests run on a local validator and in process only.
zecZEC payouts carry delisting risk. exchanges have delisted privacy coins before. a follower paid in ZEC may find fewer places to sell it.
addressesonly Sapling (zs1) addresses are accepted. unified and transparent addresses are refused.
proofsno zero-knowledge circuits. the privacy comes from the shielded pool, not from this program.
