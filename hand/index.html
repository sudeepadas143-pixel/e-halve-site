HAND

Every other page on this site describes a rule the program enforces on-chain. This one is different — it's the one place a human is actually in the loop, so it's also the one page that exists specifically to make that human checkable instead of trusted.

wallet — settle calls — open — unmatched —

The hand can do exactly one thing: call settle on an order that already exists, with a payment_post_id proving the payment happened. It cannot create an order, cannot choose who gets paid, cannot decide an amount — those are all written by a tick before the hand ever sees them. What the hand actually controls is narrower than it might sound: not whether someone gets paid, but when the hand gets around to clearing an order that's already sitting open.

That's exactly why this page exists. "The hand has no discretion" is a claim made on the how page — this page is where that claim becomes something you can check instead of take on faith. Every settle call the hand has ever made is listed here, and each one is matched against the order it claims to be paying: same handle, same amount, same tick_index and position. If a settle call doesn't match an order that was genuinely open at the time, that's visible here, not buried in a transaction log nobody reads.

This also means the hand's job is slow money moving, not fast judgment. A backlog of open orders on this page isn't a sign anything is broken — it's a queue, and the roster and tick history both remain intact regardless of how quickly the hand clears it. What would be a problem is a settle call with no matching order behind it, which is the one thing this page is built to make impossible to hide.
