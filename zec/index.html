~/z-halve/zec

SHIELDED PAYOUTS

Every z/halve payout is shielded ZEC. The halving is public. The amounts are public. Where each payout lands is not.

Not live. The program is not deployed. The payout worker has not been tested against NEAR Intents.

§1

WHAT IT IS

A tick writes orders in cents. The hand pays each one in shielded ZEC. There is no other way to be paid.

A follower submits a Sapling address once their handle is verified. The hand swaps the order's exact USDC to ZEC and sends it there. Then it settles the order on chain.

No address is ever written on chain. The program does not know where a payout goes.

§2

WHAT STAYS PUBLIC

Totals, burns and amounts stay public. Every tick, every burn, every order and its amount in cents are on chain. The halving schedule is on chain. Anyone can check all of it.

The hand's USDC deposit for each order is a public Solana transfer of the same amount. Anyone can match it to the order. What stays hidden is the Zcash address the ZEC lands in.

§3

WHO SEES WHAT

partysees
the publicorder amounts, the roster, the hand's deposit into the swap. not the zcash address.
the operatorthe handle-to-address mapping. the operator runs the payout worker and can read every address on file.
near intentsthe destination address and the amount of each swap. whether its explorers publish that has not been checked.
the programamounts and a payout reference. never an address.

This is privacy from the public, not from the operator.

§4

HOW A PAYOUT MOVES

stepwhat happens
1. verifythe follower proves the handle. the operator issues a submission token.
2. submitthe follower sends a Sapling address (zs1) with the token. it is encrypted at rest. it is never logged.
3. tickthe tick writes the order. same window, same weight, same 25 cent floor for everyone.
4. swapthe worker quotes USDC to ZEC through NEAR Intents, sends the order's exact USDC, and waits for the result.
5. deletewhen the swap succeeds the address is deleted. the next order needs a new submission.
6. settlethe hand settles the order on chain. the reference it records says nothing about the recipient.

Each order is paid at most once. The worker writes every step down before it takes it. A failed or refunded swap is retried. An unclear one stops and waits for a person. An order with no address on file waits.

§5

WHAT IS NOT DONE

itemstatus
near intentsno live test yet. the worker follows the published API. no quote, deposit or swap has been run against the real service. delivery to a shielded address has not been confirmed.
programnot deployed. it runs on a local validator and in process only.
zecZEC payouts carry delisting risk. exchanges have delisted privacy coins before. a follower paid in ZEC may find fewer places to sell it.
addressesonly Sapling (zs1) addresses are accepted. unified and transparent addresses are refused.
proofsno zero-knowledge circuits in the program. the privacy comes from the zcash shielded pool.
